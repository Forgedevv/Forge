# src/forge - LOCKED ZONE

Everything in this folder is owned by FORGE. The site builder must never create, edit, rename or
delete anything here. A blocking scan rejects any change under `src/forge/` before a push.

This zone contains all the logic that touches money, the network or the chain:

- `config.ts`: reads and validates `forge.config.json`.
- `security-headers.ts`: Content-Security-Policy allowlist, used by `next.config.ts`.
- `JupiterTrade.tsx`: Jupiter Plugin (loads the external plugin script). Only rendered by `TradePanel` once a coin graduated, with the pool handle `findLaunchpadPool` issued (it takes no mint: anything else is refused). Not part of the free-zone API: `CoinTradePanel` covers graduated coins.
- `CoinTradePanel.tsx`: trade panel of a coin page; renders `TradePanel` for the mint (FORGE buy/sell with the 0.3% platform fee on the curve, Jupiter after graduation).
- `TradePanel.tsx` / `BuyButton.tsx`: take a mint, never a pool. The pool is derived from the mint and this launchpad's two configs (`trade/launchpad-pool.ts`: `launchpadConfig` for its users' coins, `launchpadCoinConfig` for its own coin `launchpadCoinMint` only: anyone can create a pool for another mint on that config, and such a look-alike is never traded nor listed), looked up on-chain, and handed to the form as a handle only `findLaunchpadPool` can issue. `trade/core-adapter.ts` checks the pool's config again on-chain (`allowedConfigs` of `@forge/core`) and is the only place reading the FORGE fee accounts (build-time `NEXT_PUBLIC_*`, no override; `setSwapCore` works under tests only).
- `CreateCoin.tsx`: coin creation: form (image drop zone, live preview in the market row style, byte counters, error summary that focuses the first invalid field), server preparation (`/api/upload`) with a progress stepper, full cost summary shown BEFORE signing, send through the RPC relay, confirmation by polling, success screen (coin page, copy address, share on X, creator fees). The form is never wiped by a failure: an expired or failed launch, a stale review or a lower first buy is rebuilt by the server for the same coin (same mint, image and metadata) without a new upload or signature (`create/flow.ts` `rebuildLaunch`). Its parts live in `create/ui/` and all its text in `create/copy.ts`.
- `create/`: pure helpers of the creation flow (`validation`: limits from `@forge/core`, the name counted in UTF-8 bytes; `amounts`, `api`, `verify`, `chain`, `flow`; `errors`: human messages for raw wallet, RPC and program errors, shared with the claim flow; `copy`: the flow's text).
- `create/` server side of `/api/upload` (server-only modules): `prepare-handler` (coarse per-IP request limit, then a creation limit spent only by requests that passed every check, wallet signature, single-use nonce, image checks, fail closed; rebuild of a prepared launch with the capability returned by the first answer, its own limit and a per-launch cap, 410 `prepare_again` when this instance does not hold it), `image` (PNG/JPEG/WebP/GIF by magic bytes, 2 MB), `upload-client` (FORGE presigned-upload endpoint, contract in the file header; no storage key in the site), `launch-builder` (pool transaction built by `@forge/core` `buildUserCoinLaunchTx` through the RPC relay; the first buy pays the 0.3% FORGE platform fee, `create/platform-fee.ts`; core input refusals become a 400 with a human message), `server-guards` (limiter, nonces, prepared launches kept in memory for ten minutes).
- `config.ts` freezes `forge.config.json`: nothing at runtime can change the configs the site trades or creates coins on.
- `priority-fee.ts`: the priority fee of every transaction the site builds (trades on the curve, coin creation, creator fee claims): the `@forge/core` default policy, fixed at build time, priced from the recent fees read through the RPC relay and capped at 0.0005 SOL per transaction. The trade quote shows its maximum (`SWAP_MAX_PRIORITY_FEE_LAMPORTS`) before anything is built; the creation and claim summaries show the fee of the built transaction; `tx/fees.ts` refuses any transaction above the cap.
- `ClaimCreatorFees.tsx` and `claims/`: creator fee claims for the connected wallet (adapter to `@forge/core` in `claims/core-adapter.ts`; the coins of a wallet come from `listCoinsOfCreator`, the one program scan the FORGE RPC relay accepts).
- `pages/CreatorFeesPage.tsx`: the creator fee claim page of every live site, served at `/creator-fees` by the locked route `src/pages/creator-fees.tsx` (a single re-export, refused by the builder scan like `_app`). Free-zone pages may link to `/creator-fees`; when the site is sleeping or disabled the mode gate renders the mode page instead.
- `ModeGate.tsx`: app-level mode gate rendered by `src/pages/_app.tsx`. Reads the mode from `config.ts` only; when the site is sleeping or disabled it renders a page from `modes/` and nothing else.
- `modes/`: sleeping and disabled pages (and their minimal theme style). They import nothing from the free zones. The sleeping page keeps only the creator fee claim (decision D29): `modes/SleepingClaim.tsx` (wallet provider + `ClaimCreatorFees`), loaded on demand when a creator opens it.
- `AppProviders.tsx`: providers of the live site (data, wallet, toasts), the wallet provider alone (`ForgeWalletProvider`, also used by the sleeping claim) and the colour mode provider.
- `ModeBanner.tsx`: banner shown instead of an action when the site is sleeping or disabled.
- `data/`: coin data. `client.ts` (Jupiter data API client) and `DataStreamProvider.tsx` (trench stream). Lists and stream updates are filtered on this launchpad's configs, then on its coins (`isListedLaunchpadCoin`: no other mint on the launchpad coin config). `source.ts` picks the source: the data API is primary on mainnet; coin lists, coin info and descriptions fall back to the chain (`GET /api/coins`) when it fails, times out or returns nothing (then the data API is skipped for 30 s), and devnet never calls it. Chart, holders and transactions have no fallback: they throw `DataUnavailableError` and the UI shows its unavailable state (`chart/ChartUnavailable.tsx`, free-zone `components/ui/DataUnavailable.tsx`). When the stream is unreachable, and on devnet, the coin lists and coin info are polled every 15 s while the tab is visible. Source switches are logged with `console.debug`, nothing else.
- `data/onchain/` (server only, behind the locked route `src/pages/api/coins.ts`): this launchpad's coins read through the FORGE RPC relay with the server token: one config pool scan of the users config (`listPoolStatesOfConfig` of `@forge/core`; the relay serves that scan to server tokens only), the launchpad coin's pool read directly, mints, Metaplex metadata and the Pyth SOL/USD price in `getMultipleAccounts` batches (`accounts.ts` decoders), metadata JSON from the site storage only. Results are cached (lists 15 s, one coin 10 s, CDN `s-maxage`), served stale on read errors, deduplicated and budgeted (`service.ts`); `pools.ts` builds the data API shaped entries. Without a relay the route answers empty data.
- `chart/`: TradingView chart (loads an external script and queries the data API). Without price history (data API down, or devnet) it shows `ChartUnavailable` instead, and never loads the script on devnet.
- `token-icon/`: token images (dynamic image URLs).
- `CoinLink.tsx`: link to the launchpad coin on Jupiter (sleeping page).
- `mode-guard.ts`: what each mode allows (`capabilitiesFor`: a sleeping site allows the creator fee claim only); API routes answer 503 when the site is sleeping or disabled (the claim needs no API route: it goes from the browser to the FORGE RPC relay).

Rules for the free zones (`src/theme`, `src/content`, `src/components`, `src/pages`): no `fetch`, no
dynamic URL, no dynamic `img src`, no external script. Import a component from here instead.
